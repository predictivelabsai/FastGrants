# FastGrants

**FastGrants** is an open-source **grant / EU-funds lifecycle platform** built
with [FastHTML](https://fastht.ml) — a server-side, HTMX-driven workspace for
funding bodies that *administer* grants end to end: publish calls, take in
applications, award agreements, disburse against milestones, and monitor
beneficiary reporting. Python-first, no JavaScript framework, with **Plotly**
dashboards and a built-in **AI assistant** grounded in your live programme.

*Run the money, not the paperwork.* Runs on port **5015**.

> **Synthetic data only — no PII.** Everything ships and runs on deterministic,
> fully synthetic data generated by `seed.py`. FastGrants **administers** grants
> (intake → award → disburse → monitor); it does not score or evaluate proposals.

## Quickstart (native)

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.sample .env          # optional — add an LLM key for free-form AI chat
.venv/bin/python web_app.py  # http://localhost:5015  (self-seeds on first boot)
```

Login: `admin@fastgrants.example` / `FastGrants2026$` (override in `.env`).
Rebuild demo data: `.venv/bin/python seed.py`.

## Run with Docker

```bash
docker compose up --build      # http://localhost:5015
```

`Dockerfile` (python:3.12-slim, port 5015) seeds on first boot;
`docker-compose.yml` mounts a `fastgrants-data` volume at `/data` so the SQLite
DB survives rebuilds.

## Module tour

- **Dashboard** (`/`) — programme KPIs (budget, allocated, disbursed, open
  applications), **Plotly** budget allocated-vs-disbursed by call, a
  disbursement-rate gauge, the application pipeline, and an **overdue-milestone**
  worklist.
- **Calls & Programmes** (`/calls`) — funding calls with budget, open/close
  dates and status; drill into a call to see all of its applications.
- **Applications** (`/applications`) — the intake queue with the decision
  workflow **Submitted → Under Review → Approved / Rejected**, project summary
  and supporting documents. **Approving auto-creates a grant agreement** with
  three disbursement tranches.
- **Grants & Agreements** (`/grants`) — awarded grants, milestone tranches, and
  one-click **disbursement** with disbursed-vs-awarded progress bars.
- **Beneficiary Reports** (`/reports`) — periodic progress + financial reports;
  **approving a report disburses** its linked milestone tranche.
- **AI Assistant** (right rail) — eligibility Q&A over call rules and
  application summarisation over a **live snapshot** of the programme. Plain-English
  questions stream from a configurable LLM provider; **slash-commands**
  (`/budget`, `/pipeline`, `/calls`, `/review`, `/grants`, `/overdue`, `/kpi`,
  `/help`) resolve instantly with **no API key**.

## Lifecycle & disbursement engine

Each approved application becomes a **grant agreement** whose award is split into
three tranches (pre-financing 40% / interim 40% / final 20%), each a milestone
with a due date. Disbursing a milestone — directly, or by approving the matching
beneficiary report — records the payment and rolls up into the programme's
`allocated` vs `disbursed` figures. Milestones past their due date and still
unpaid surface on the dashboard and via `/overdue`.

## Configuration

`.env` (see `.env.sample`). Free-form AI chat needs one provider:

```ini
MODEL_PROVIDER=xai          # xai | openai | anthropic | google
MODEL_NAME=grok-4-1-fast-reasoning
XAI_API_KEY=...
```

Without a key the whole app still works and slash-commands answer from SQLite.

## Architecture

```
web_app.py        routes, auth, SSE chat endpoint, boot
db.py             SQLite schema + lifecycle/disbursement engine + read helpers
seed.py           deterministic synthetic-data generator
web/layout.py     3-pane shell, CSS, chat JS
web/views.py      page renderers
web/charts.py     Plotly chart specs (budget, pipeline, gauge)
web/ai.py         slash-commands + multi-provider streaming chat
```
